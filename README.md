# روشتة برو

أتمتة حقيقية لصرف الروشتات على **نايس دير** + متابعة واتساب ويب.
كل خطوة في البرنامج بتتنفذ فعليًا على الموقع — مفيش أي بيانات وهمية أو محاكاة.

## تشغيل سريع

```bash
npm install
npm run build      # بناء الواجهة (ملف واحد في dist/)
npm start          # تشغيل نسخة سطح المكتب (Electron)
```

فحوصات:

```bash
npm run typecheck     # TypeScript
npm test              # قواعد الصلاحية + الشهري + تصنيف الردود + قراءة HTML نايس دير الحقيقي
npm run check:snippets # سكربتات الأتمتة اللي بتتنفذ داخل صفحات نايس دير/واتساب
```

> الواجهة في المتصفح بتظهر شاشة توضيحية فقط: الأتمتة محتاجة نوافذ سطح المكتب.

### قراءة الجدولين

| الجدول | المصدر | الرقم المرجعي | التاريخ | النوع |
| --- | --- | --- | --- | --- |
| `#Table` (Pre-Approvals) | `pre-approval` | نص `a.hyperLink` / `approval.PreApprovalId` | **Pre-Approval Date** | `Type` |
| `#Table2` (Claims) | `claim` | **ND Claim ID** (`a.hyperLink`) | **Claim Date** | `Claim Type` |

- رقم التليفون من `.NDClaimIDResult`.
- أي صف فيه كلمة تدل على الشهري في `Type` أو `Claim Type` بيتسجل **شهري**.
- الصفحة بتتعاد تحميلها قبل بحث ساب جديد عشان ما تُنسبش استمارات ساب قديم لساب جديد.

### قاعدة الصلاحية

- استمارات **Claims**: خلال آخر 6 أيام من تاريخ اليوم (قابل للتعديل من الإعداد).
- استمارات **Pre-Approval**: مستثناة من الـ 6 أيام، لكن لازم تكون في **الشهر الحالي**.
- **الشهري**: لكل ساب، لو آخر استمارة شهرية في الشهر الحالي مرّ عليها 6 أيام أو أكتر → متاح،
  غير كده غير متاح. البرنامج بيعرضها لكل ساب والمستخدم بيأكّد أو يعدّل يدويًا.

### التقاط صورة الروشتة (سبب مشكلة «الروشتة مش بتظهر»)

نافذة `/Apps/NewPharmacy/Beneficiary/PrescriptionImgs?...` بتفتح من الرقم المرجعي. البرنامج:

1. يلتقط رابط النافذة أو تنقّل الصفحة بعد الضغط على الرقم المرجعي.
2. يفتحها في نافذة مخفية بنفس جلسة الكوكيز (+ Referer الصفحة الأصلية).
3. يقرأ `<img>` الأكبر داخل الصفحة عبر `canvas` ثم `fetch` بالكوكيز.
4. لو الصورة محمية (tainted) → تصوير النافذة `capturePage` كصورة PNG حقيقية.
5. الصورة بتتحفظ كـ `dataURL` في **IndexedDB** بمفتاح `${الساب}::${المصدر}::${الرقم المرجعي}`،
   فالظهور مضمون حتى بعد قفل البرنامج، ومفيش مربعات فاضية بدون سبب.

## الوضع المرعب ⚡ (السرعة)

السرعة مش «تخطي خطوات» — كل خطوة حقيقية، بس من غير أي انتظار ثابت:

1. **بحث واحد لكل ساب**: اختيار الباير → قفل المودال → تنضيف الجدولين → كتابة الساب → `#SearchId`
   → استقرار الصفوف → قراءة الجدولين والتليفون، كله في نداء صفحة واحد.
2. **بدل الانتظار الثابت**: كل الخطوات بتستنى على `requestAnimationFrame` لحد ما الشرط يتحقق
   (الصفوف بقت ثابتة ≥ ١٢٠ مللي، أو ظهرت `dataTables_empty`، أو خلصت مهلة ٣.٥ ثانية).
3. **نتائج الساب بتفضل محفوظة**: بعد تصوير الروشتة بنرجع لصفحة النتائج (`goBack`) بدل تحميل جديد،
   وكل استمارة بتتطلب على نفس النافذة اللي عليها سابها (affinity) — يعني بحث واحد لكل ساب
   مهما كان عدد استماراته.
4. **خط إنتاج**: في الوضع المرعب كل ساب بيتجرد وبتتصور استماراته على نفس النافذة فورًا،
   بدل ما الجرد كله يخلص وبعدها نبدأ التصوير.
5. **التصوير**: poll سريع على `<img>` → `canvas` بـ JPEG عالي الجودة (تصغير لو أكبر من ٢٢٠٠px)
   → `fetch` بالكوكيز → لقطة نافذة مصغّرة كخطة أخيرة.
6. **الإرجاع في الخلفية**: `#btn-DeleteClaim` بيشتغل في طابور مستقل (٣ نوافذ) ومش بيوقف تصوير الاستمارة اللي بعدها.
7. **تسخين مسبق**: النوافذ بتفتح صفحة البحث مرة واحدة قبل بدء الشغل (`nd:warmup`).

## القياس والاستقرار (بدون سحابة)

- **قياس كل خطوة** بالمللي ثانية (بحث / فتح الروشتة / التقاط / إرجاع) في `src/lib/metrics.ts`،
  ولوحة «قياس السرعة الحقيقي» بتعرض المتوسط و p95 والاختناق الحالي وأبطأ ١٠ سابات،
  وتصدّر CSV بتوقيت كل خطوة + شيتات «توقيت الخطوات» و«أبطأ السابات» في تقرير الجلسة.
- **تصنيف الأخطاء** (`src/lib/retry.ts`): دائم (ما بيتعادش) / جلسة منتهية (دخول تلقائي) /
  إعداد غلط (رسالة فيها الحل) / مؤقت (إعادة بمهلة أسّية وعشوائية مع ميزانية للجلسة).
- **ضبط النوافذ** (`src/lib/tune.ts`): سقف من رام وأنوية الجهاز، وزيادة/تقليل كل ١٥ ثانية
  من القياس الحقيقي، ورفض الزيادة لو الذاكرة الحرة قلت.
- **حماية**: وقف تلقائي لو أول ٥ سابات فشلوا، watchdog للنوافذ المتعلقة، منع تشغيل جلستين،
  استكمال من آخر ساب، كاش جرد اليوم، وإعادة فاشلي الصور والإرجاع مرة واحدة في آخر الجلسة.

## المراحل في الواجهة

1. **الإعداد**: يوزر/باسورد نايس دير، اختيار الباير، ملف السابات (الساب + الاسم + مكان العمل)،
   فلترة مكان العمل، اختبار الدخول، وتجربة ساب واحد قبل التشغيل الكامل.
2. **التشغيل**: «١) جرد الاستمارات» ثم «٢) جلب صور الروشتات» — نوافذ متوازية (٥ / ٨ / ١٢ / ١٦) وكل نافذة على ساب مستقل.
   لو عدد السابات أقل من عدد النوافذ، استمارات الساب الواحد بتتقسم على أكتر من نافذة بدل ما النوافذ تقف فاضية.
3. **القرار**: صورة كل روشتة → «بها دواء / بدون دواء»، وقائمة الشهري لكل ساب بتأكيد يدوي،
   وإعادة الجلب أو إعادة جرد أي ساب.
4. **النتيجة**: رسائل واتساب (بها دواء / الشهري متاح) بقالب حر، إرسال متتابع بفاصل،
   مزامنة الردود وتصنيفها (موافق / رافض / طلب تأجيل) بكلمات يحددها المستخدم.

## الواجهة باختصار

- **زرار واحد في كل مرة:** شريط ثابت تحت كل الشاشات بيقول «الخطوة الجاية» بالاسم مع عدّاد المراحل
  (التجهيز → الجرد → الصور → القرار → الإرسال)، و`Ctrl+Enter` بينفّذها من أي مكان.
- **لوحة أوامر `Ctrl+K`** فيها كل شاشة وكل أمر (جرد، صور، إعادة متعثرة، تصدير إكسل).
- **لوحة جاهزية** قبل التشغيل: بتقول الناقص (ملف / باير / دخول / واتساب) وكل سطر ناقص بيروح لمكان حلّه.
- **إشعارات فيها تراجع** بدل نوافذ تأكيد، و**مؤشر حفظ** في الهيدر («بيتحفظ…» / «محفوظ ١٢:٣٠»).
- **جولة تعريف** ٤ خطوات أول مرة + دليل اختصارات بـ`؟` + تلميحات سياقية (بحد أقصى ٢).
- إعدادات جديدة: `autoLogin` (دخول تلقائي)، `reducedMotion` (تقليل الحركة).
- التفاصيل الكاملة وأرقام النقرات قبل/بعد: [UX_REVIEW.md](./UX_REVIEW.md).

## ملاحظات

- الإرجاع (`Delete`) مفعّل افتراضيًا زي طريقة الصرف، ومعاه تنبيه واضح في الإعداد، وينفع يتقفل قبل التشغيل.
  والنافذة اللي بترجّع مبتحمّلش صور، فبتخلص أسرع.
- واتساب: الأرقام بتتظبط لصيغة `+20` قبل الإرسال، وفاصل الإرسال فيه عشوائية ±، وفيه حد يومي للرسائل.
- شاشة القرار: مفاتيح `1` (بها دواء) و`2` (بدون) ومسافة (اللي بعدها) و`R` لتدوير الصورة و`Ctrl+Z` للتراجع،
  والانتقال التلقائي للروشتة اللي بعدها، والافتراضي فلتر «لم يُحسم»، وزرار «استكمال من آخر روشتة».

## اللي لسه (متعمّدش في النسخة دي)

- تخزين الصور كـ Blob بدل base64 ونقلها ArrayBuffer (توفير ~٣٠٪ حجم بس بيمس محرك الصور كله).
- virtualization لقائمة القرار، وتحميل السكربتات بالطلب — `vite-plugin-singlefile` بيحط كل حاجة في ملف واحد.
- قراءة ردود واتساب من قائمة المحادثات مرة واحدة، ونسخة headless.
- إعادة تقسيم شاشة الإعداد لتابات (`دخول / ملف / تشغيل / واتساب`) — دلوقتي المتقدّم مطوي والجاهزية فوق.
- بيانات الدخول وكل الحالة محفوظة محليًا على الجهاز (`localStorage` + `IndexedDB`).
- تغليف EXE: [DESKTOP.md](./DESKTOP.md).
