# روشتة برو

نظام تحليل استمارات نايس دير والمتابعة — واجهة React + Vite، ونسخة سطح مكتب Electron (Windows EXE).

## تشغيل سريع

```bash
npm install
npm run dev      # للواجهة في المتصفح (وضع تجريبي)
npm run build    # بناء الواجهة في dist/
npm start        # تشغيل نسخة سطح المكتب بعد البناء
```

اختبارات:

```bash
npm test         # قواعد صلاحية الشهري (6 أيام/الشهر)
npm run smoke    # اختبار دخان لمسار عرض الروشتات كامل
```

## إصلاح مشكلة «الروشتة مش بتظهر في واجهة البرنامج»

المشكلة كانت في طبقة البيانات والعرض، مش في نايس دير. الأسباب الخمسة اللي كانت موجودة والإصلاحات:

| السبب | التأثير | الإصلاح |
| --- | --- | --- |
| الصور كانت بتتحفظ في `localStorage` مع باقي الحالة | أول ما الصور تكتر، الحفظ يفشل بـ Quota، وكل الحالات تضيع بصمت | الصور اتنقلت لـ **IndexedDB** (`src/lib/imageStore.ts`)، والحالة الصغيرة بس اللي بتتحفظ في `localStorage` |
| حالة `imagesHydrated` كانت بتتحفظ | بعد قفل البرنامج وفتحه، الاسترجاع بيتخطّى، فالصور تفضل مربعات فاضية | بتتصفّر في `partialize` وبتترجع من التخزين عند الفتح (`hydrateImages`) |
| مفتاح الاستمارة كان ترتيبها/رقم النافذة | مع ٥–١٠ نوافذ متوازية، صورة ساب تتربط بساب تاني، وفيه حالات تختفي | المفتاح بقى `${الساب}::${رقم الاستمارة}` — ثابت ومستقل عن النوافذ (`caseKey`) |
| تحديث المحرك كان بيعمل استبدال كامل للحالة | صورة جاهزة كانت تتمسح لما ييجي تحديث بدون صورة، أو قرار المستخدم يضيع | `mergeRx` و`mergeCase` بيحموا الصورة والقرارات من التحديثات |
| فشل جلب الصورة كان بيسيب الحالة «قيد الجلب» للأبد | مربع فاضي بدون تفسير ولا زرار | كل فشل بقى حالة `failed` **بسبب مكتوب** وزرار «إعادة المحاولة» + تسجيل في السابات المتعثرة |

بالإضافة إلى:

- **عارض روشتة حقيقي**: `src/components/RxViewer.tsx` — يعرض تحميل/فشل/صورة تالفة برسالة واضحة، مع عارض مكبّر (تكبير، تصغير، تنزيل، Esc).
- **تحميل مؤجل للصور** (IntersectionObserver) عشان الشاشة ما تتجمّدش مع مئات الروشتات.
- **لوحة تشخيص** في شاشة الإعداد تقول السبب المباشر لو الصورة مش ظاهرة (جسر سطح المكتب، الوضع التجريبي، مخزن الصور، حالات غير متسقة).
- **إيقاف الجلسة** بيعلّم استمارات الطابور «متوقف — أعد المحاولة» بدل ما تفضل معلّقة.
- **إعادة فتح البرنامج أثناء جلسة** بيقفل الجلسة السابقة بشكل نظيف مع رسالة، بدل ما يفضل شايل «شغّالة» بدون محرك.

## المسار الكامل

1. **الإعداد**: ملف Excel (ورقة المرضى + ورقة الاستمارات)، مكان العمل والباير، بيانات نايس دير وواتساب، المواعيد.
2. **التشغيل**: محرك متوازي (٢–١٠ نوافذ، تلقائي بالقياس) → بحث → صورة (٣ محاولات) → حفظ → إعادة محاولة تلقائية.
3. **القرار**: كل استمارة بكارت صورتها وحالتها وقرار «الأدوية متاحة/غير متاحة» و«الشهري متاح/غير متاح».
4. **النتيجة**: رسائل الواتساب المتتابعة، تصنيف الردود، وتصدير الإكسل.

## ملاحظات تقنية

- قاعدة الشهري: مرة كل ٦ أيام داخل نفس الشهر (`src/lib/eligibility.ts`) ومغطاة باختبارات في `npm test`.
- رقم الساب والاستمارة هما المصدر الوحيد للهوية — مفيش أي اعتماد على ترتيب الصفوف.
- نسخة سطح المكتب: `electron/main.cjs` (نوافذ نايس دير المخفية) و`electron/preload.cjs` (جسر آمن). تفاصيل التغليف في [DESKTOP.md](./DESKTOP.md).
